# 정수 시너지 (2026-11-07 — 사용자 승인 · 구현됨, 결정 번호 ES1~ES6)

> 사용자 요청: "정수의 패시브와 액티브가 따로 노는 데 그치지 않고 서로 이어져 하나의 전투 전략이 되게" → 설계안 보고 → 사용자 "교체하고 다른 추가 정수를 만들 때도 프롬프트 내용이 반영되도록". **B1~B6 · C1~C4 구현됨(§11), 앞으로의 규칙 §10.** §2 · §3 표는 설계 당시(교체 전) 데이터다.
> 조사는 실제 데이터(`data/essences` 68종 · `data/skills` · `data/statuses.json`)와 코드(`EssenceSet` · `Passives` · `StatusSet` · `DamageCalc`)로 했다. 아래 표는 데이터에서 자동으로 뽑았다.

## 0. 결론 먼저

1. **이미 있는 연계 구조가 쓸 만하다.** 정수 하나 = 패시브 1 + 색에 맞는 액티브 1(수호자는 액티브 전부)이고, 패시브에 "그 상태인 적에게 피해 ×" 같은 **범용 반응 키**(`power_vs_status` · `hit_vs_status` · `counter_while` · `skip_bonus_vs` · `on_kill`)가 있다. 그래서 "A 정수의 액티브가 상태를 걸고 → B 정수의 패시브가 그 상태에 반응"하는 연계가 **별도 코드 없이** 이미 돌아간다(출혈 · 속박 · 중독 · 공포 · 저주 · 방어 태세).
2. **문제는 축이 한쪽으로 쏠린 것.** 거는 정수는 많은데 반응하는 정수가 **없는** 상태가 대부분이다 — 기절(11종이 거는데 반응 0), 실명(9 · 0), 은신(7 · 0), 서리(6 · 0), 철벽(6 · 0), 혼미(5 · 0), 끌어들이기(4 · 0). 이 상태들은 지금 "덤 효과"일 뿐 전략이 되지 않는다.
3. **제안의 중심 = 스탯만 주는 밋밋한 패시브(10여 종 — 코볼트 · 벽두더지 · 거석병 · 곰 · 웨어울프 · 홉고블린 · 샌드맨 · 불카르 …) 중 여섯을 반응 패시브로 바꾸기.** 기존 범용 키만 써서 **데이터 교체로** 빈 축 다섯을 채운다(기절 · 실명 · 철벽 · 끌어들이기 · 혼미 · 서리). 반응 패시브는 등급 7~9의 서로 다른 정수에 하나씩 나눠, 특정 정수 · 고등급이 최적 조합을 독점하지 않게 한다.
4. **작은 코드 확장 넷**: ① 상태 반응 배율 상한(중첩 폭주 방지) ② 은신 중 공격 보너스 키(은신 축) ③ 처치하면 게이지(처치 연쇄 — 행동 순서) ④ Tab 정수 화면 · 정수 획득 창에 **연계 표시**(어느 액티브가 어느 패시브를 깨우는지 — 데이터에서 자동으로).
5. **따로 "시너지 표"(정수 A+B = 보너스)는 만들지 않기를 권한다** — 상태 축이 이미 N×M 조합을 만들고, 짝 보너스 표는 "정답 조합"과 숨은 규칙을 만든다(§7 대안). 새 색 정수도 필요 없다(색이 이미 아홉).

## 1. 구조 조사 (실제 코드)

| 항목 | 실제 구현 |
|---|---|
| 정수 장착 | `EssenceSet.absorb → _attach`: 패시브 수정자(출처 `essence:<id>`) · `Actor.add_passive` · 굴린 스탯 · 생명력 · 색에 맞는 액티브 `learn_skill`. 슬롯 = 레벨 × 1 |
| 제거 · 잠금 | `remove` · `sync_slots`(레벨이 내려가면 무작위로 잠금) → `_detach`가 출처째 떼고 `remove_passive` · `forget_skill`. 잠긴 정수는 효과 없음 |
| 같은 효과 중복 | 패시브 id · 스킬의 `essence_of`가 겹치면 흡수 불가(`conflict_keys`) — 같은 패시브를 두 번 가질 수 없다 |
| 세이브 · 로드 | `EssenceSet.to_dict / load_dict → reattach_all` — 패시브 · 스킬이 다시 붙는다 |
| 패시브 반응 계산 | 맞힐 때마다 **지금 붙은 패시브 목록**을 훑는다(`Passives.damage_mult_vs` · `hit_bonus_vs` · `after_hit`) — 상태를 저장하지 않으므로 장착 · 잠금 · 제거가 즉시 반영된다 |
| 배율 겹침 | `power_vs_status`는 **패시브끼리 곱한다**(출혈: 피 냄새 1.125 × 어설픈 검술 1.1 = 1.24). 반격은 가장 큰 것 하나(`counter_while` max) |
| 무한 연쇄 방지(있음) | 중첩 상한 출혈 3 · 독 5 · 서리 3(3 → 빙결). 기절 · 빙결 · 마비 · 석화는 풀린 뒤 잠깐 면역(`after_immune`). 반사 · 반격 피해는 적중 효과를 다시 부르지 않는다(`DamageApply.hurt`) |
| 전투 한정 | 상태 `battle_only` · 차례 단위 지속은 전투가 끝나면 풀린다(`clear_temporary`) |
| 색 | 빨강 · 파랑 · 초록 · 노랑 · 보라 · 회색 · 하양 · 검정 · 갈색(9) — 같은 정수라도 색에 따라 액티브가 다르다 |

## 5. 실제 발동 흐름(예)

**① 기절 짓밟기(B1)** — 코볼트 방패병 빨강 방패 밀치기 + 홉고블린 패시브
1. 내 차례: 방패 밀치기(1.2, 기절 25% — 큰 몸짓 중이면 50%, CB6) → 적 [기절].
2. 행동 순서 판을 본다 — 기절한 적의 차례는 건너뛰지만, 그 차례가 시작될 때 기절이 풀린다. 그 **전에** 내 차례가 한 번 더 오면(민첩) →
3. 강한 단일기 × 1.25. 그 뒤 적은 잠깐 기절 면역(무한 기절 없음).

**② 굳은 자세 반격(B3)** — 노움 파랑 굳히기 + 거석병 패시브
1. 굳히기: 철벽(물리 내성 +50%, 2턴) + 끌어들이기.
2. 적들의 근접 공격이 나에게 몰린다 → 맞을 때마다 반격 0.5(코볼트 방패병 B4가 있어도 반격은 가장 큰 하나만).
3. 철벽이 끝나기 전 다시 굳히기(쿨 3) 사이에 기세 · 공격 — "방어로 받아치는" 순환.

**③ 출혈 사냥(A1 + A2)** — 칼날늑대 빨강 + 핏빛 칼날늑대(보라) 패시브 · 액티브
1. 물어뜯기로 출혈(최대 3중) → 피 냄새 ×1.125, 매 차례 출혈.
2. 3중이 되면 피 핥기로 소모 폭발. 출혈이 사라지므로 다시 쌓아야 한다(무한 아님).

**④ 실명 사냥(B2)** — 고블린 노랑 모래 뿌리기 + 아울베어 패시브
1. 모래(실명 67.5%) → 적 명중 −30(나를 덜 맞힌다).
2. 같은 3턴 동안 내 공격 ×1.2 — 막기와 공격이 한 상태로 이어진다.

## 7. 고려했지만 권하지 않는 것

- **명시적 짝 보너스 표**(정수 A + B를 같이 가지면 보너스): 쉬워 보이지만 "정답 조합"이 생기고, 왜 세지는지 화면으로 보이지 않는다. 상태 축(거는 쪽 ↔ 받는 쪽)은 같은 결과를 더 열린 조합으로 낸다.
- **새 색 정수**: 색은 "같은 정수에서 어떤 액티브를 받나"를 정한다. 연계는 색이 아니라 상태가 잇는다 — 새 색이 풀어 줄 빈칸이 없다.
- **같은 계열 세트 보너스**(늑대 둘 = …): 몬스터 계열이 정수 고르기를 좁힌다. 필요하면 나중에.
