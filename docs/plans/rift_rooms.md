# 균열 구역 재기획 — "모든 공간에 이유를" (2026-10-30, 기획안 · 적용 안 함)

> 사용자 요청: "균열 스테이지 공간에 이유가 있으면 좋겠다. 이유 없는 빈 공간·지형은 없으면 좋겠다. 공간이 있으면 대기 중인 몬스터가 있고 아이템을 얻을 수 있게 — 잡템이든 좋은 아이템이든. 지금은 넓은데 별게 없어서 재미없는 스피드런이 됐다."
> 지금 상태 정리는 `rift_terrain.md`, 배치도는 `rift_boards/current/`(지금) · `rift_boards/*.png`(예전 — 구역 이름이 적혀 있다).

## 0. 왜 스피드런이 되는가

| 지금 | 결과 |
|---|---|
| 넓은 바닥 대부분이 "그냥 지나가는 땅"이다(예: 탄광 4 공동 2894칸, 묘 2 대전당, 빙하굴 2·4 분지) | 들를 이유가 없다 |
| 대기 무리(RF23)는 "시작·출구에서 가장 먼 칸"에 **무작위로** 선다 — 장소와 상관없다 | 몬스터가 왜 거기 있는지 없고, 피하면 그만이다 |
| 잡템은 아무 소품에서나, 빈손 40~50%, 값 40~600 | 뒤지는 게 귀찮고 얻는 게 작다 |
| 히든 피스는 챕터당 0~2개 | 대부분의 방은 아무것도 주지 않는다 |
| 처치 보상은 마석·정수뿐(RF17) | 싸울수록 손해(생명력·시간) |
| 수호자전은 준비 없이도 똑같다 | 탐험해서 얻는 게 수호자전을 바꾸지 않는다 |

**핵심**: 지금 균열에서 "곁길로 새는 것"은 손해만 있다. 곁길이 이득이 되게 바꾼다.

## 1. 원칙

1. **구역 = 이유 + 지키는 것 + 얻는 것.** 챕터를 이름 있는 구역 3~6개로 나눈다(예전 배치도의 "서쪽 작업장·고블린 야영지·화약 창고" 같은 것). 구역마다:
   - **이유**: 이 공간이 무엇이었나(장면) — 그 이유가 몬스터 구성·소품·보상을 정한다.
   - **지키는 무리**: 이유에 맞는 몬스터(고블린 야영지 = 고블린, 무기고 = 병사 데드맨). 무작위 대기 무리(RF23)를 이것으로 바꾼다.
   - **보관함**: 그 구역의 보상이 모인 소품 하나(상자·무기 거치대·석관·썰매 …) — 확정 보상.
2. **이유를 못 붙이는 땅은 없앤다.** 지도를 줄이거나(벽·외곽으로 채움) 새 구역으로 만든다. "넓어 보이게"는 솟은 외곽·낭떠러지 너머 풍경이 맡는다(AM49·AM50).
3. **큰길은 비고, 곁길에 몰린다.** 시작 → 출구 큰길에는 보관함을 두지 않는다. 곁가지 구역에 보상이 있어서 스피드런 = 보급 없이 수호자전.
4. **얻는 것이 수호자전을 바꾼다.** 균열 안에서만 쓰는 보급품(§2-②)이 그 균열 수호자·몬스터에 맞춰져 있다 — 탐험을 많이 할수록 수호자전이 쉬워진다.
5. **화면으로 보인다(UI19).** 보관함은 눈에 띄는 그림(빛·크기), 몬스터는 이유에 맞는 자세(일하는 고블린·먹는 구울·자는 예티 — 그림이 생기면). 규칙 설명 문구는 띄우지 않는다.

## 2. 얻는 것 — 네 가지(RF17 "미궁 물건은 못 가지고 나간다"를 지킨다)

| 종류 | 나가면 | 무엇 | 어디서 |
|---|---|---|---|
| ① **잡템**(지금 RF19) | 남는다(팔기) | 은화·금화·광석·장신구. 보관함은 **확정 2~4개 + 비싼 쪽 가중** | 보관함 · 일반 소품(지금처럼, 빈손 확률 더 높게) |
| ② **균열 보급품**(새) | 사라진다(`rift_bound`) | 그 균열 안에서만 쓰는 포션·전투 물건 — 수호자·그 균열 몬스터에 맞춤 | 보관함(주 보상) |
| ③ **귀한 것**(지금 히든 피스) | 남는다 | 소소한 영구 스탯 · 원정 한두 번 값 | 챕터당 1~2곳, 조건 있는 보관함 |
| ④ **단서**(새, 선택) | 사라진다 | 수호자의 약점 기록 — 모으면 수호자전 시작에 이로운 상태 | 균열마다 3곳 |

### ④ 단서(선택)
- 균열마다 3곳(벽화·일지 대신 장면 물체: 성채 = 처형 명부, 빙하굴 = 얼어붙은 사냥꾼의 표식, 탄광 = 광부의 경고 낙서, 묘 = 지금 벽화). 하나 얻을 때마다 수호자전 시작에 "간파" 1단계(피해 +5% 또는 첫 차례 +). 강철의 묘 벽화(수수께끼 힌트)와 같은 틀.

## 3. 보관함 규칙(안)

- 구역의 지키는 무리가 **남아 있으면** 보관함을 열 때 그 무리가 알아챈다(바로 전투). 처치했거나 **들키지 않고 등 뒤로 다가가면**(V20 — 등을 돌리고 있으면 모른다) 그냥 연다. → 싸우거나, 몰래 하거나.
- 보관함은 이번 균열에서 한 번(지금 잡템처럼 `scavenged`).
- 가방이 차면 열지 않은 채 남는다.
- 보관함 표(`data/rift_caches.json` — 지금 `scavenge.json`과 같은 틀): {잡템 묶음, 보급품, 확률로 귀한 것}.

## 5. 숫자(안)

- 구역 = 챕터당 3~6, 보관함 = 구역당 하나(큰길 제외).
- 균열 하나 다 돌면: 보급품 6~10개 · 잡템 약 3~5만(지금 약 1~2만) · 귀한 것 지금 그대로.
- 대기 무리 수는 지금(RF23 1~5)과 비슷 — 자리만 구역으로.

## 6. 만드는 순서(안)

1. **녹색 탄광으로 시범**(지도가 가장 단순하고 구역 이름이 이미 뚜렷하다): 구역 데이터 · 보관함 타일 · 보급품 4종(그림 포함) · 무리 자리.
   - 데이터: 챕터 JSON `rooms: [{id, name_ko, guard: [몬스터…], cache: <표 id>}]` + 설계도 `marks.rooms`(구역 가운데·보관함 자리). posts는 rooms가 없는 챕터에만.
   - 코드: 보관함 열기(interact `rift_cache` — 지키는 무리가 남았고 들키면 전투), 무리를 구역 가운데에(`RiftPosts` 대신).
   - 점검: sim_rift가 모든 보관함에 걸어서 닿는지, 테스트로 보관함 한 번·들킴·가방 참.
2. 사용자가 해 보고 괜찮으면 나머지 셋 + 빈 땅 자르기(설계도 손질 → `rift_boards.py`로 다시 그림).
3. 단서(④) — 원하면.

## 7. 정할 것

1. 보관함 여는 조건 — (가) 지키는 무리를 처치해야 열림 (나) **남아 있어도 열 수 있지만 들키면 전투(몰래 가능)** (다) 그냥 열림.
2. 보상 무게 — 보급품 중심(수호자전 대비) / 잡템 중심(돈) / 반반.
3. 빈 땅 — **자르기**(지도 작게) / 새 구역으로 채우기.
4. 단서(④) 넣을지.
5. 시범 균열 — 녹색 탄광(추천) / 다른 곳.
