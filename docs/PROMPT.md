# 던전 앤 스톤 (Godot 4) — Claude Code 마스터 프롬프트

> **사용법**: 이 파일 전체를 Claude Code 첫 메시지로 붙여넣거나, 프로젝트 루트에 `PROMPT.md`로 저장한 뒤

## 1. 역할과 목표

너는 Godot 4 전문 게임 개발자이자 시스템 설계자다. 소설 『게임 속 바바리안으로 살아남기』의 작중 게임 **「던전 앤 스톤」**을 구현하는 비상업 팬 프로젝트를 만든다.

- 장르: **2D 3/4 쿼터뷰(비스듬히 내려다보는 시점) 던전 크롤러 + 턴제 전투 + 하드코어 로그라이크 RPG** — 시점은 §3의 '카메라/뷰'를 따른다.
- 분위기: 『피어 앤 헝거』 같은 어둡고 잔혹하고 불친절한 분위기. 한 번의 판단 실수가 캐릭터의 사망으로 이어진다.
- 전투: 『클레어 옵스퀴르: 33원정대』처럼 **민첩이 턴 순서와 횟수를 결정**하는 턴제.
- 목표: 설계도만이 아니라 **실제로 실행해서 테스트 플레이할 수 있는 빌드**를 단계별로 완성한다. 볼륨(층, 몬스터, 정수, 아이템, 스탯)이 계속 커질 것을 전제로, **콘텐츠는 코드가 아니라 데이터로 추가**되는 구조로 만든다.

## 2. 작업 운영 규칙 (중요)

1. **질문하지 말고 진행한다.** 모호한 부분은 합리적으로 가정하고 `docs/ASSUMPTIONS.md`에 "가정 / 이유 / 바꾸는 방법"을 한 줄씩 기록한다.
2. 가장 먼저 `CLAUDE.md`(프로젝트 규칙·구조·실행 명령 요약), `docs/DESIGN.md`(이 프롬프트의 설계 요약), `docs/PROGRESS.md`(마일스톤 체크리스트 + 현재 상태 + 다음 할 일)를 만든다. **작업이 끝날 때마다 PROGRESS.md를 갱신**한다. 사용자는 PC의 Claude Code와, Godot이 없는 환경(모바일 웹 등)을 번갈아 쓸 수 있으므로 어떤 세션에서도 이 문서만 읽으면 이어갈 수 있어야 한다.
3. **Godot 에디터 없이 텍스트만으로 작성·수정 가능한 구조**를 유지한다. `.tscn`은 최소한으로 쓰고, UI와 노드 트리는 가능한 한 GDScript 코드로 구성한다. 바이너리 에셋 조작이 필요한 작업은 피한다.
4. 검증: Godot이 설치된 환경이면 `godot --version`으로 버전을 확인하고 그 버전에 맞춘다. 헤드리스 스모크 테스트(`godot --headless --path . --quit` 및 `tests/run_tests.gd`)를 돌려 통과시킨 뒤에만 "완료"로 표시한다. Godot이 없는 환경이면 정적 검토만 하고 PROGRESS.md에 **"미검증(Godot 실행 필요)"**이라고 명시한다. 검증하지 않은 것을 검증했다고 쓰지 않는다.
5. 마일스톤마다 **항상 실행 가능한 상태**로 커밋한다(깨진 상태로 끝내지 않는다). 커밋 메시지는 한국어로 짧게.
6. 큰 파일 하나에 몰아넣지 않는다. 한 스크립트는 한 책임, 가능하면 300줄 이내.

## 3. 기술 스택과 제약

- **Godot 4.x (4.3 이상 권장), GDScript, 정적 타이핑 필수**(`var hp: int`, `func f(a: int) -> void`). 모든 주요 클래스에 `class_name`.
- GDExtension, 외부 플러그인, 스레드 의존 기능은 쓰지 않는다(웹 내보내기 호환 유지).
- **한글 폰트**: Godot 기본 폰트는 한글이 빠질 수 있다. OFL 라이선스 한글 폰트(예: Noto Sans KR 또는 Pretendard)를 `assets/fonts/`에 넣고 프로젝트 기본 테마 폰트로 지정한다. 모든 UI 텍스트는 **한국어**이며, 문자열은 하드코딩하지 말고 `data/strings/ko.json`(또는 Godot 번역 CSV)에서 키로 불러온다.
- **그래픽**: 각 데이터 항목에 `sprite` 경로 필드를 두어 나중에 이미지 파일만 교체할 수 있게 한다. 아트 때문에 개발이 멈추면 안 된다.
- **카메라/뷰 (중요)**: **완전히 수직으로 내려다보는 탑뷰가 아니다.** 『피어 앤 헝거』처럼 **비스듬히 위에서 내려다보는 3/4 시점(오블리크 탑다운)**이다. 벽과 지형에 높이가 있어 벽의 **윗면과 정면(앞면)**이 함께 보이고, 캐릭터·몬스터는 위에서 본 점이 아니라 **정면/측면이 보이는 전신 스프라이트(최소 4방향)**로 그린다.
  - 로직은 2D 그리드(이동·충돌·FOV·길찾기는 바닥 평면 기준)이고, **렌더링만 3/4 시점**으로 처리한다(3D 엔진/물리 불필요).
  - Y-정렬(`y_sort_enabled`)로 앞뒤 가림을 처리한다. 캐릭터가 벽 뒤로 가려질 때는 반투명 또는 실루엣으로 표시해 위치를 잃지 않게 한다.
  - 타일 규격 예시(조정 가능): 바닥 32×32, 벽은 바닥 접점 기준 위로 높이가 올라가는 세로로 긴 타일(예: 32×48 이상). 충돌·광원 차폐(`LightOccluder2D`)는 **벽이 바닥에 닿는 발치 영역** 기준으로 둔다.
  - 전투 화면도 같은 시점의 무대에서 아군과 적이 마주 보는 대열로 보여준다(위치 이동 없음).
  - 시점 관련 값(타일 크기, 벽 높이, 스프라이트 방향 수)은 `data/balance.json` 또는 `data/render.json`에 모아 나중에 바꿀 수 있게 한다.
  - 임시 그래픽 단계에서도 이 시점이 보이도록 만든다(벽은 윗면+앞면 두 색으로 구분되는 도형).
- 연출 방향: 저채도 어두운 팔레트, `CanvasModulate` + `PointLight2D`(횃불), 비네트와 필름 그레인 셰이더(`texture_filter = nearest`).

## 4. 세계관과 원작 반영 규칙

### 4.1 참고 자료 (설정의 1차 출처)

아래 설정을 **반영한다**. 세계관과 설정에 관한 질문이 있다면 관련 문서를 검색하지 말고 사용자아게 질문하고 문서 텍스트를 붙여달라고 요청하되, 그동안은 §4.3·§11의 요약으로 진행한다.

- 정수 관련 설정은 우선 공백으로 두고 나중에 작업한다.
### 4.2 반드시 지킬 것

- 구현 대상은 **작중 게임 「던전 앤 스톤」 그 자체**다. 플레이어는 게임 속 탐험가다.
- **원작 등장인물은 등장시키지 않는다**(주인공, 동료, 길드·왕가·마탑의 실명 인물, 황금 세대 인물 등 모든 실명 인물). NPC는 직함/역할로만 둔다("길드 접수원", "대장장이", "신전 사제").
- 현실 쪽 설정(악령·빙의, 고스트 버스터즈 커뮤니티, GM, 치트판 배율, 한국 플레이어 등)은 **넣지 않는다.** 게임 안의 설정만 쓴다.
- 원작 문장·대사를 그대로 복사하지 않는다. 설정(규칙·수치·명칭)만 가져오고 문장은 새로 쓴다.
- 이 게임은 "공략을 모르면 올라갈 수 없지만, 모든 것은 공략 가능하게 설계된" 게임이다. **히든 피스, 숨은 조건, 정보의 가치**를 핵심 재미로 삼는다. 불합리하게 막히는 요소는 만들지 않는다.

### 4.3 핵심 설정 요약

- **라프도니아**: 마녀의 저주로 황폐해진 세계에 남은 유일한 성채 도시. 14개 구역(1 황도 카르논, 2 부터 5 컴멜비 상업지구, 6 노움트리, 7 부터 13 라비기온[포탈 광장 위치], 14 비프론). 탐험가는 라비기온의 **차원광장**에서 한 달에 한 번 열리는 포탈로 미궁에 들어간다.
- **미궁**: 1~10층 + 지하 1층. 층마다 폐쇄 시간이 정해져 있고, 시간이 되면 강제로 도시로 귀환(도시에는 항상 **입장 다음 날 정오**에 복귀). **1~5층은 매번 리셋**, 6층부터 시간이 연속된다. 대부분의 층은 빛을 잡아먹어서 **광원이 있어도 가시거리가 10m에 못 미친다**(상한값; 층별 예외와 근거는 §9). 부산물과 시신은 '왜곡' 마법 없이는 반출 불가(마석과 아이템 취급 물품은 가능).
- **마석**: 화폐의 근원. 환전소에서 스톤으로 교환. 9등급 마석 ≈ 20스톤(돌빵 1개), 8등급 ≈ 100스톤.
- **몬스터**: 처치하면 몸이 빛 먼지로 흩어지며 장비도 함께 사라지고 드롭만 남는다. 탐험가의 시신에는 관심이 없다. 일정 시간 뒤 정해진 지점에서 리스폰하고, **미궁에 머문 시간이 길수록 개체 수가 늘어난다.** 이 게임의 핵심은 **상성**이다(상성이 안 맞으면 절대 못 잡는 적이 있고, 맞으면 수월하다).
- **정수**: 몬스터에게서 낮은 확률로 드롭. 흡수하면 스탯과 스킬(이능)을 얻는다. 몬스터와 정수는 **9등급(최하) → 1등급(최상)**. 탐험가 등급은 영혼에 새겨진 정수의 총량으로 정해진다.
- **경험치(공적)**: **같은 몬스터는 최초 1회 처치 때만** 준다(도감 채우기). 지급량은 등급별로 **(10 − 등급)**: 9등급 1, 8등급 2, 7등급 3, 6등급 4, 5등급 5, 4등급 6, 3등급 7, 2등급 8, 1등급 9. 상위 변이종 +1, 균열 수호자 +3(같은 수호자도 **반복 획득**), 8층 이상 수호자 +5, 계층군주 +15. 포탈 최초 개방은 소량(약 2).
- **레벨**: 레벨업 시 **영혼력 최대치 상승** + 정수 슬롯 +1. 영혼력은 5레벨까지 +10씩, 이후 +30씩. 레벨이 하락하면 그만큼 정수 슬롯이 무작위로 잠긴다.
- **허기**: 미궁 안에서만 작동. 식량·간식 필요.
- **계층군주**: 층의 지배자. 1층은 **드레드피어(공포의 군주)** — 한 곳에 5인 이상 모여 3일 차 이후 머물면 확률적으로 소환되고(하루 안에 사실상 확정), 6시간마다 재소환 가능. 드레드피어를 **연속 9번** 처치하면 또 다른 1층 군주 **베르자크(심연의 군주)**가 층을 배회한다(심연의 안개: 사용 효과·액티브 스킬 봉인, 마력 효율 1/4, 5등급 심연 변종 출현 — 후반 확장). 소환 전에는 길드에 토벌 신청서를 내야 한다(법률). (설정상 역사 최초의 계층군주 토벌 이후 균열이 생겨나기 시작했으며, 게임 내에서는 균열이 처음부터 열릴 수 있다.)
- **균열**: 층 안의 인스턴스 던전(챕터 구조 + 수호자). 정수 드롭률이 높다. **수호자 드롭: 정수 33%, 넘버스 아이템 33%, 균열석 66%**(각각 독립). 수호자는 HP 구간·장치로 정해진 패턴을 반복한다.
- **넘버스 아이템**: 균열 수호자에게서만 얻는 고유 장비. 번호가 낮을수록 희귀·강력(싱글 1에서9, 더블 10에서99, 트리플 100에서999 …). 귀속 각인, 공명 보구(세트 효과), 부적(한 종류만 적용) 개념이 있다.
- **직업/역할군**: 수호자(탱커), 근접 딜러, 원거리 딜러, 탐색꾼, 신관, 마법사 등. **전직 시스템 대신 정수와 장비 조합으로 컨셉이 만들어진다.** (마법사·신관은 정수를 못 먹는 대신 별도 자원을 쓰는 직군 — 후반 확장.)
- **종족 6종**: 인간, 바바리안, 드워프, 요정, 수인, 용인. 초기에는 **인간·바바리안** 구현, 나머지는 데이터만 추가하면 열리게 한다.
- **약탈자·배신**: 다른 탐험가를 노리는 약탈자와 동료 NPC의 배신이 존재한다(후반 확장 훅).
- **차원 붕괴(후반 확장)**: 극히 드물게 발생하는 재앙. 모든 타일이 무작위 포탈이 되어 파티와 몬스터가 무작위 위치로 이동한다.

## 5. 게임 루프

```
도시(준비: 길드 정보, 상점, 정수 정리, 휴식)
  → 포탈 개방일에 차원광장에서 입장 (시작 위치 랜덤)
  → 층 탐험·사냥·히든 피스 수색 (시간·허기·시야 제약)
  → 다음 층 포탈 발견 or 폐쇄 시간까지 버티기
  → 강제 귀환(다음 날 정오) → 마석 환전·정수 흡수·장비 정비
  → 다음 달 포탈 개방일까지 대기 → 반복
사망 = 해당 캐릭터 영구 삭제 → 새 캐릭터로 처음부터(사망 기록은 '묘비 목록'에 남김)
```

## 6. 스탯과 자원

**스탯**(성장·장비·정수로 변하는 능력치)과 **자원**(소모하고 회복하는 게이지)을 **완전히 분리**한다. 영혼력은 스탯이 아니라 자원이다.

### 6.1 핵심 스탯 5개 (1차 구현)

| ID | 이름 | 역할 |
|---|---|---|
| `str` | 근력 | 물리 공격력. (확장: 소지 중량) |
| `agi` | 민첩 | 이동 속도, 치명타율, **턴 횟수·순서** |
| `p_res` | 물리내성 | 물리 방어력 |
| `m_res` | 항마력 | 마법 방어력, 상태이상 저항 (400 이상 시 '제압 면역' — 확장 훅) |
| `int` | 정신력 | 마법 공격력 (원작에서는 정신계 내성 성격이 강하지만, 이 프로젝트에서는 사용자 정의에 따라 마법 공격력으로 쓴다) |

- 캐릭터 생성 시 종족·시작 템플릿(전사/검사/창술사/궁수 등)이 정한 **범위 안에서 기본 스탯이 무작위로** 정해진다(제한된 횟수의 리롤 허용).


### 6.2 자원(Resource) 시스템 — 생명력 · 영혼력 · 허기

| ID | 이름 | 최대치 | 회복 | 임계/0일 때 |
|---|---|---|---|---|
| `hp` | 생명력 | 기본값 + 레벨 보정 + 스탯 보정(`p_res`, `str` 일부 반영; 계수는 `balance.json`) | 자연재생(확장 스탯), 포션, 신성 주문, 휴식 | 0 → 사망(치명상 규칙은 §8) |
| `soul` | 영혼력(MP) | **스탯이 아니라 레벨 테이블로 결정**(Lv5까지 레벨당 +10, 이후 +30). 정수·업적 보너스(예: 5층 최초 도달 +20, 8층 최초 도달 +50)와 일부 아이템으로만 증가 | **최대치에 비례한 재생**(턴/시간당 비율) | 0 → '영혼탈진' 상태(스킬 사용 불가 + 디버프) |
| `hunger` | 허기 | 100(고정, 확장 가능) | 식량·간식 섭취 | 아래 참조 |

- **허기**: 값은 **포만도**(100 = 배부름, 0 = 아사 직전)로 저장하고 UI에는 '허기' 게이지로 표시한다. **미궁 안에서만** 시간 경과(이동·전투·휴식)에 따라 감소하며 도시에서는 정지·숨김. 식욕(확장 스탯)이 감소율을 보정한다. 임계값: ≤30% '허기'(소폭 패널티), ≤10% '굶주림'(근력·민첩 대폭 감소, 자연재생 정지), 0 → 아사 피해(생명력 지속 감소). 값의 방향(포만도 vs 허기도)은 데이터 한 줄로 뒤집을 수 있게 하고 ASSUMPTIONS.md에 기록한다.
- **구조 (필수)**
  - `ResourceDef`(리소스/JSON, `data/resources.json`): `id`, `name_ko`, `color`, `max_formula`(스탯·레벨·수정자 키를 참조), `regen`(rate, basis: max_ratio/flat, trigger: turn/time/rest), `scope`(always/dungeon_only/combat_only), `thresholds`[{at_ratio, direction, apply_status | event}], `on_zero`(kill/status/event), `visible`.
  - `ResourcePool` 컴포넌트: `current/max`, `modify(delta, source)`, `can_afford(costs)`, `spend(costs)`, 시그널 `changed`·`threshold_crossed`·`depleted`. 최대치도 `Modifier` 시스템(`resource_max`)을 쓴다.
  - **스킬·아이템·이벤트의 코스트는 어떤 자원이든 참조 가능**해야 한다(`{"soul": 5}`, `{"hp": 10}` …). 새 자원 추가 = `resources.json`에 한 항목.
  - 후속 자원 후보(정의만 예약): 기력(스태미나 — 10% 이하에서 행동 불가, 지구력 영향), 마력(마법사), 신성력(신관), 스트레스(간식으로 완화).

### 6.3 확장 가능한 스탯 구조 (필수)

원작에는 육체·정신·이능 아래에 **수천 개의 세부 스탯**이 있다. 따라서 스탯을 `if/else`나 하드코딩된 변수로 만들지 말고 **레지스트리**로 만든다.

- `StatDef` 리소스/JSON: `id`, `name_ko`, `group`(육체/정신/이능/특수), `rarity`, `parent`(옵션), `coef`(옵션: 세부 스탯 1당 상위 스탯 증가 계수), `visible`(투명 스탯 여부).
- `StatBlock`: `get_value(id)`는 `기본값 + Σ(modifier)`를 계산. `Modifier`는 `source_id`(정수·장비·버프 등), `stat_id`, `flat`, `percent`, `duration`을 가진다. **출처별로 추가/제거**할 수 있어야 한다(정수 삭제, 장비 해제, 버프 만료).
- 계산 순서: 기본값 → 합연산(flat) → 곱연산(percent) → 상·하한 클램프.
- 새 스탯 추가 = `data/stats.json`에 한 줄 + (필요하면) 효과를 읽는 계산 규칙 1개. 기존 코드를 수정하지 않는 것이 목표다.
- 나중에 넣을 세부 스탯 후보(레지스트리에 **정의만** 미리 등록하고 효과는 점진적으로 연결): 유연성(회피·치명 미세 증가), 골강도, 시각(원거리 사거리·가시 범위), 체중(넉백·둔기 피해), 식욕(허기 감소율), 인지력, 고통내성, 자연재생력(생명력 재생), 투쟁심(공포 저항), 후각, 지구력(기력 최대치·재생), 육감(히든 탐지), 영혼 재생력(영혼력 재생 보정), 속성 감응도(화염·냉기 등)·속성 내성(화염·번개·대지·냉기·독·신성·어둠), 절삭력, 도약력, 시야, 근질량, 행운(치명타 등 확률), 통제력, 적응력(디버프 감쇠), 수복력(회복량 보정), 청각, 명성, 지지도.

### 6.4 파생 수치 기본식 (모두 `data/balance.json`에서 조정 가능)

- 물리 공격력 = 무기 공격력 + `str` × 계수 / 마법 공격력 = 스킬 기본값 + `int` × 계수
- 피해 = 공격력 × 스킬 배율 × `100 / (100 + 방어값)` (물리는 `p_res`, 마법은 `m_res`), 속성·상성 보정 별도
- 치명타율 = 기본 + `agi` × 계수 (+ 행운 등 확장 스탯), 치명타 배율 기본 1.5
- 탐험 이동 시간 비용 = 기본값 / (1 + `agi` × 계수)
- 최대 생명력 = 기본 + 레벨 × a + `p_res` × b + `str` × c (a, b, c는 balance.json)
- 영혼력 재생량 = 현재 최대 영혼력 × 재생 비율(+ 영혼 재생력 보정)

## 7. 레벨·정수·경험치

- **경험치**: 몬스터 종류별 최초 처치 시에만 지급(`bestiary` 기록, 캐릭터 단위 영구 기록). 지급량은 (10 − 등급)을 기본으로 하고 변이·수호자·군주 보너스를 더한다(§4.3). 수호자 보너스(+3)는 반복 획득 가능.
- **레벨업**: 영혼력 최대치 증가(§6.2) + 정수 슬롯 +1. 필요 경험치는 레벨이 오를수록 폭발적으로 증가하게 한다(원작 기준: 1~4층 몬스터를 전부 잡아도 5렙에 아슬아슬하게 못 미치므로, 정수로 성장하며 5층 이상으로 가야 한다).
- **정수 슬롯**: 기본 슬롯 수 = 레벨(가정; `balance.json`에서 조정). 슬롯이 부족하면 새 정수를 흡수하려면 기존 정수를 삭제(대신전)해야 한다.
- **정수 데이터**: `id`, `name_ko`, `grade`(9~1), `source_monster`, `color`(정수 색: 같은 몬스터도 색에 따라 능력이 다름), `stat_ranges`(드롭 시 등급 범위 안에서 **무작위 롤**), `resource_mods`(영혼력 등 자원 최대치 보너스, 드물게), `skills`(패시브/액티브), `tags`(속성 등).
- 정수 흡수는 **되돌릴 수 없다**(삭제는 대신전에서 비용을 내고만 가능). 흡수 전 확인 UI와 "정수 조합 미리보기"(길드 정보를 산 경우에만 상세 표시)를 둔다.
- 레벨 상한: 1차 구현은 **레벨 1~5**, 데이터상 원본 기준 11까지 확장 가능하게 설계(`꿈꾸는 영혼` 같은 초희귀 경험치 아이템 훅).
- **정보의 가치**: 몬스터 스탯·정수 효과·히든 피스 정보는 처음엔 `???`로 표시되고, 직접 관찰하거나 길드에서 정보(예: 하급 정수 총합본)를 구매하면 공개된다. `Knowledge` 시스템으로 구현.

## 8. 전투 시스템 (턴제, 33원정대 스타일)

- 전투는 탐험 맵에서 적과 접촉/발각되면 시작된다(랜덤 인카운터 없음). 적은 맵에서 눈에 보이고, 경계/추적 상태가 있다.
- **CTB 타임라인 방식 (민첩 → 순서와 횟수)**
  - 각 전투원은 행동 게이지를 가진다. 틱마다 `gauge += agi`(또는 속도 파생값), 임계값(예: 100) 이상이 되면 행동하고 `gauge -= 임계값 + 스킬의 delay_cost`.
  - 빠른 유닛은 느린 유닛보다 **더 자주** 행동한다(= 턴 횟수 차이). 2배 빠르면 대략 2번 행동.
  - 화면 상단에 **다음 행동 10개 타임라인**을 미리 시뮬레이션해 표시한다. 스킬 `delay_cost`로 강한 기술일수록 다음 턴이 늦어지게 한다.
  - 난수는 시드 고정 가능한 `RandomNumberGenerator`로 분리해 테스트 가능하게 한다.
- **커맨드**: 공격, 스킬(코스트는 임의의 자원 — 영혼력이 기본), 방어(가드), 아이템, 도주(민첩 비교, 실패 가능), 정보 보기. 영혼력이 0이면 '영혼탈진'으로 스킬을 못 쓴다.
- **파티 구조**: 아군 1~5명까지 영입할 수 있으나 초기 플레이는 플레이어 단독 파티로 진행한다.(1차 빌드는 플레이어 단독 + 길드에서 고용하는 동료 최대 2명). 전투 배치는 위치 이동 없이 대열(전열/후열)만 둔다.
- **하드코어 규칙**: 레벨이 높아도 치명상 판정이 있다. `lethal_chance`(급소) 판정은 아군·적 모두에게 적용되며, 이 규칙은 설정에서 끌 수 없다(난이도의 핵심). 단 확률은 데이터로 조정한다.
- **상태이상**(레지스트리, 데이터 정의): 출혈, 중독, 기절, 공포, 통각강화, 저체온증, 화상 등. 부상(골절·절단 등)은 1차에는 '출혈/골절' 정도만, 구조는 부위 확장이 가능하게 `InjuryDef`로 분리.
- **스킬/효과는 데이터 기반**: `SkillDef`(대상 유형, 코스트, delay_cost, 효과 목록, 쿨타임) + `EffectDef`(type: damage / heal / apply_status / modify_stat / summon …). 효과 타입은 `effects/` 폴더에 스크립트 1개 = 타입 1개로 등록하는 **핸들러 레지스트리** 방식. 새 효과 추가 시 기존 코드를 고치지 않는다.
- **적 AI**: 데이터에 우선순위 규칙 리스트(`condition → skill`)로 정의하는 단순 규칙 기반. 무리 행동(고블린은 열댓 마리씩 뭉쳐 다님), 도주, 증원 호출 같은 훅을 둔다.
- **상성 시스템(핵심 재미)**: 몬스터는 `type`(이능계 / 영체류 / 육체)과 `family`(언데드, 냉기·짐승, 어둠, 망령, 디버프 주술사, 타워형, 비행종, 야수종, 자연종, 악마형, 식물종, 메이지 클래스, 기생 개체, 환상종, 어류종 …) 태그를 가지고, `immunities`/`weaknesses` 데이터로 상성을 표현한다. 예: 영체류는 물리 면역(대신 대체로 등급 대비 약함), 언데드는 신성·화염에 약하고 **코어(약점)**를 파괴해야 죽는 개체가 있음(스켈레톤은 갈비뼈 사이 핵, 데스핀드는 머리), 냉기·짐승 계열은 전기에 약함, 어둠 계열은 태양에 약함, 비행종은 근접 딜러의 카운터, 타워형은 이동 불가, 메이지형은 평타가 약함. `weak_point` 필드와 "약점 노리기" 커맨드(명중 하락, 성공 시 큰 피해)를 지원한다. **상성이 안 맞으면 절대 못 잡는 적이 있되, 항상 공략법이 존재해야 한다.**
- **반응형 연출(옵션)**: 33원정대의 회피·패링 타이밍 이벤트를 위한 `ReactionEvent` 인터페이스만 만들어 두고, **기본값은 꺼짐**(2차 확장).

## 9. 탐험·맵·시간·시야

- **그리드 이동**(4방향, 렌더링은 §3의 3/4 시점). 1타일 = N미터(`meters_per_tile`, 기본 1m로 가정하고 ASSUMPTIONS.md에 기록). **FOV + 안개(탐험한 곳만 흐리게 기억)**로 구현.
- **시야/가시거리 — 출처 재검토 결과**
  - 원문 근거 ①(미궁 문서 개요): 대부분의 층에 **빛을 잡아먹는 성질**이 있어 **10m만 떨어져도 육안으로 볼 수 없다.**
  - 원문 근거 ②(같은 문서, 기록 항목 앞부분): 미궁이 어둡기 때문에 **불을 켜도 가시거리가 반경 10m도 되지 않아** 아는 사람과 마주치기 어렵다.
  - 결론: **10m는 '기본 시야 반경'이 아니라 '광원이 있어도 넘지 못하는 상한(10m 미만)'**이다. 초기 프롬프트의 "기본 10m" 표현은 부정확했으므로 이 기준을 따른다.
  - 층별 예외(원문): **1층 수정동굴**은 벽·천장 수정이 광원이라 횃불이 필요 없고 암흑지대는 극히 일부(구체 수치 없음 → placeholder). **2층**은 밤처럼 깜깜하나 천장의 빛 덕에 가로등 없는 골목길 정도의 밝기이고, 망자의 땅은 유독 가시거리가 좁음(수치 없음). **드레드피어 소환 중** 시야 반경 2m, **베르자크의 심연의 안개** 약 2m. 지하 1층은 바위섬 약 100m, 인간섬 약 10m, 도서관 내부 약 5m. 6층 대해처럼 하늘이 열린 필드는 별도 제한 없음.
  - 구현: 층 데이터에 `visibility_cap_m`(상한)을 두고, 광원별 `light_radius_m`(횃불·라이트 젬·수정 등)와 비교해 **유효 시야 = min(상한, 광원 반경)**으로 계산한다. 상한이나 반경 수치가 원문에 없으면 **임시값을 쓰고 `"source": "placeholder"`**로 표기한다(예: 횃불 반경은 원문에 수치가 없다).
  - 횃불: 한 번 켜면 약 3일 유지(원문), 투구 홈에 꽂아 쓰는 방식이 흔함(손을 자유롭게). 시야 관련 확장 스탯(시각·시야·인지력)은 상한 안에서 보정하는 용도로만 연결한다.
- **시간 시스템**: 이동·전투·휴식이 게임 내 시간을 소모한다. 층별 폐쇄 시간에 도달하면 강제 귀환(1층 168시간, 2층 240시간, 3층 15일, 4층 23일, 5층 30일, 6층 60일, 7층 75일). 대기/수면으로 시간을 넘길 수 있고(위험 이벤트 포함), 시간 소모량은 `balance.json`에서 조정.
- **맵 생성**: 층 입장마다 **절차적 생성**(`FloorGenerator` 인터페이스). 수정동굴은 셀룰러 오토마타 계열 동굴 + **고정 랜드마크**(네모 수정 삼거리, 큰바위 옆 연못 등, 입장할 때마다 지형은 바뀌지만 랜드마크는 존재), 중심부 대현자 기념비(안전지대), 동서남북 4개의 2층 포탈. 층 타입별 생성기를 추가할 수 있게 한다.
- **이벤트**: 함정, 상자, 샛길/숨은 벽(육감·탐색 스탯으로 발견), 제단, 히든 피스 트리거. 이벤트는 `data/events/*.json` + 핸들러 레지스트리.
- **저장**: 단일 슬롯 영구 저장 + **사망 시 삭제**(세이브 스컴 방지). 도시 귀환, 층 이동 시 자동 저장. 저장 파일은 버전 필드를 가지고 마이그레이션 가능하게 한다.

## 10. 도시: 라프도니아 (허브)

메뉴 기반 UI(도시 안에서 캐릭터를 직접 걸어 다니는 맵은 1차에서 불필요)로 시작하고, 시설은 데이터로 정의한다.

- **탐험가 길드**: 정보 구매(정수 총합본 등), 파티 구성/동료 고용, 의뢰 접수, 등급 확인.
- **환전소**: 마석 → 스톤. **잡화점**(포션·횃불·식량·소모품, 전리품 판매), **대장간**(장비 구매·수리), **대신전**(치료, 정수 삭제), **여관**(회복·시간 경과·특식), **훈련장**(이능 시험 — 도시에서 이능 사용 가능한 유일한 곳, 정수 스킬 확인), **중앙 거래소**(후반 확장).
- **월 달력**: 포탈은 월 1회 개방. 개방일 전까지 대기·준비. 도시 복귀는 항상 다음 날 정오.
- **경제 기준 가격(스케일 참고)**: 한 끼 300스톤, 여관 특식 800, 컴멜비 여관 1박 9,000, 횃불 10,000, 상급 포션 200,000, 최상급 포션 1,030,000, 하급 방탄조끼 360,000, 한 달 생활비는 넉넉하게 70,000.
- (선택/후반) **세금 모드**: 20세 이후 매년 세금, 미납 시 사형(=게임오버). 켜고 끌 수 있는 난이도 옵션으로 설계.

### 11.5 계층군주 드레드피어 (1차 구현, 턴제 번역)

- **소환**: 3일 차 이후 한 곳에 `summon_min_party`명 이상(원작 5명; 1차 테스트 기본값 3, ASSUMPTIONS.md에 기록)이 머물면 시간에 따라 확률이 지수적으로 증가(하루 안에 사실상 확정). 전조로 불길한 시스템 로그 2종(**원작 문장은 복사하지 말고 새로 쓴다**)이 뜨고, 동굴 수정의 광채가 보라색에서 적색으로 변한다. 소환되면 결속 해제, **시야 반경 2m 제한**, 포탈은 닫히지 않고 일반 몬스터도 변하지 않는다. 실패하면 트리거를 발동한 캐릭터만 죽이고 조용히 사라진다. 처치 시 수정이 꺼진다. 리스폰 6시간. 사전에 길드 토벌 신청서가 필요하다.
- **페이즈(원작의 실시간 오오라/타이머를 라운드 기반으로 환산)**
  1. 구더기 토큰 소환 + 오오라 [갉아먹는 공포](피격 시 정신력 감소 누적, 받은 피해에 비례해 보스 분노 상승).
  2. N라운드마다 버프가 **레이드 끝까지 중첩**(첫 버프를 보지 않고 넘기는 것이 최선, 4회 이상부터 급격히 어려워짐). [스며드는 공포](명중률 하락, 일정 확률로 아군 오인 공격), [역병 확산](오오라 영구 강화). 정신력·영혼력·육체 수치 감소가 각각 최대치에 닿으면 '공포' / '무기력증'(영혼력 재생 불가, 스킬 중단) / '탈진'(육체 스탯 30% 감소, 행동 비용이 영혼력으로 전환).
  3. [배신의 장막]: 서로를 식별할 수 없어 **타겟이 무작위화**되고 오인 공격 피해 ×5. 탱커가 위치를 지키고 신관이 광역 치유로 버티는 것이 정석. 이후 [보호기제]로 껍질 속에 숨는 **그로기 창**이 딜 타임. 증오 수치가 최대가 되면 레이드는 사실상 실패.
  4. (후속 확장) 5인 이하일 때 열리는 전용 맵 '고독의 무저갱', 고블린 마비독 상태에서 열리는 히든 피스 '순례자의 동굴'.
- **보상**: 계층군주 처치 경험치 +15, 정수 없음, 부산물 가치 낮음(클랜 승급 요건 충족). 균열 개방 조건과는 별개다(균열은 §11.2의 조건으로 열린다).
- **베르자크(심연의 군주)**: 드레드피어 9연속 처치 시 출현 — 후반 확장(M7).

설계 원칙:

1. **데이터 주도**: 몬스터·정수·스킬·아이템·층·균열·이벤트·시설은 전부 JSON. `DataRegistry`가 로드하고 `tools/validate_data.gd`가 검증한다. 새 콘텐츠 추가는 JSON만 편집하는 것이 정상 경로여야 한다.
2. **레지스트리/핸들러 패턴**: 효과 타입, 이벤트 타입, 상태이상, 층 생성기, 시설, 적 AI 조건은 모두 id → 핸들러 등록 방식.
3. **느슨한 결합**: 시스템 간 통신은 `EventBus` 시그널(예: `monster_killed`, `essence_absorbed`, `time_advanced`, `floor_closing`)로. 업적·도감·퀘스트가 나중에 이벤트를 구독만 하면 붙는다.
4. **컴포넌트 구성**: `Actor`는 `StatBlock`, `StatusSet`, `EssenceSlots`, `Inventory`, `SkillSet` 컴포넌트를 조합한다.
5. **모든 수치는 `balance.json`**: 코드에 매직 넘버를 두지 않는다.
6. **저장 호환성**: 저장 데이터는 id 참조 + 롤된 값만 저장하고(정의 전체 복사 금지), 버전 필드를 둔다.
7. **디버그 패널(F1)** 필수: 정수 지급, 레벨/스탯 조정, 몬스터 소환, 시간 스킵, 포탈 즉시 개방, 무적 토글, 시드 고정. 테스트 플레이 속도를 위해 1차 빌드부터 넣는다.

## 14. 1차 플레이 가능 범위 (Vertical Slice)

다음을 모두 할 수 있으면 "테스트 플레이 가능"이다.

1. 새 게임 → 종족(인간/바바리안)·템플릿 선택 → 스탯 랜덤 롤
2. 도시에서 길드·상점·환전·대신전 이용, 포탈 개방일 대기 후 1층 입장
3. 1층 탐험(시야 제한·횃불·허기 게이지·시간 경과), 칼날늑대·노움·구울·고블린 전투(타임라인, 민첩에 따른 순서·횟수 차이가 눈에 보임)
4. 첫 처치 경험치 → 레벨업 → 정수 드롭/흡수 → 스킬 사용
5. 2층 필드 1~2개 진입, 8등급 마석을 제단에 바쳐 균열(빙하굴/녹색 탄광) 열기, 챕터 클리어 후 수호자 전투와 넘버스 아이템 드롭
6. 1층 계층군주 드레드피어 소환·토벌(동료 파티 구성 필요)
7. 층 폐쇄 시 강제 귀환, 사망 시 영구 삭제 + 묘비 목록
8. 저장/불러오기, 디버그 패널

## 15. 품질 기준

- 전투와 탐험에서 **치명적인 오류 없이 30분 이상 연속 플레이** 가능
- 모든 데이터 파일이 `validate_data.gd`를 통과
- 새 몬스터/정수/스킬을 JSON만 추가해 넣었을 때 **코드 수정 없이** 게임에 나타남(이 검증을 실제로 한 번 시연하고 PROGRESS.md에 기록)
- 밸런스는 "초반이 잔혹하지만 정보와 준비로 극복 가능"한 것이 목표. 불합리한 즉사 요소 금지
